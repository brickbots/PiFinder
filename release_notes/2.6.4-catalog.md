# PiFinder 2.6.4: Catalog Changes

This release replaces PiFinder's object database with a new build. We checked every catalog against its published sources, fixed what was wrong, and cited a source for each fix. Most changes are small, but together they touch thousands of objects. The full record is in [#670](https://github.com/brickbots/PiFinder/issues/670) and the rebuild in [#697](https://github.com/brickbots/PiFinder/pull/697).

## What you will notice

- **One star, one object.** A star that several catalogs list (Bright Named, SAC Doubles, SAC Red Stars, RASC Doubles, the variable stars, WDS) is now a single object. Mizar is one double star, not three separate objects. Every catalog entry still opens it, and object details still step through its entries.
- **Accurate star positions and brightness.** Each of these stars now takes its position from the Hipparcos star catalog, and its magnitude too where Hipparcos measured that star alone.
- **Official star names.** Stars show their IAU name first, for example Acrab, not Graffias. Older names still work in search.
- **A new Named Stars catalog** (Objects → By Catalog → Stars…) lists all 578 stars with an IAU name, numbered by their Hipparcos number: Vega is Nam 91262. 213 of them were not in PiFinder before, among them Miaplacidus, Naos and Pherkad.
- **Star lists open with names shown.** Planets, comets and the star, double-star, asterism and variable-star catalogs open in the names view, with real names before catalog numbers. SQUARE still changes the view.
- **The magnitude filter no longer hides bright double stars.** A double now filters by its brighter star, not by the average of the two.
- **Double stars follow WDS.** A star is a double star if WDS lists it in a pair, unless WDS marks every pair it has as dubious, or gives no magnitude for the companion; those are now single stars. A bright star that WDS lists, such as Vega or Canopus, is one double-star object. Each entry shows its separation and both magnitudes, so you can judge whether you can split it.
- **Better names and types for deep-sky objects.** Messier objects show their common name first (M 82 is the Cigar Galaxy). NGC/IC numbers that point at nothing are marked "Not found". Duplicate entries now share one object. For example, Collinder 189 is the same object as M 44.
- **Observing lists** read designations the same way as the catalog. "Cr 399" and "Collinder 399" both find the Coathanger, and an ambiguous name such as "H 24" no longer finds the wrong object.
- In any object list you can now type up to six digits to jump to a number.

## Things that moved or went away

- **About 1,500 entries moved by more than 5′.** Most are WDS double stars just south of the celestial equator, which the old import placed north of it. Sharpless objects now use their J2000 positions.
- **Five SAC Doubles entries are gone** (SaM 149, 729, 779, 1585 and 2056). SAC marks them as rejected pairs. Each star is still in the database through its WDS entry.
- **Still missing:** Barnard's six "a" dark nebulae (B 44a and others, [#665](https://github.com/brickbots/PiFinder/issues/665)). They are planned for a later release.

## Your data

Your observation log and saved observing lists keep working. They store catalog designations, which have not changed. An observation of a removed SaM entry stays in your log but no longer marks an object as observed. The first start after the update takes a little longer while PiFinder builds its catalog cache again.
