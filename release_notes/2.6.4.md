# PiFinder v2.6.4 Release Notes

2.6.4 is mostly a catalog release. Every catalog was checked against its published sources and the object database was rebuilt from the result, so names, positions, types and magnitudes are now cited rather than inherited. A star that several catalogs list is now one object, and a new **Named Stars** catalog holds every star with an official IAU name. The catalog changes have their own page: [PiFinder 2.6.4: Catalog Changes](2.6.4-catalog.md).

Around that, three things you may notice. **Each telescope now keeps its own alignment**, so moving the PiFinder between two telescopes no longer means aligning again. A long-standing fault that could quietly undo a saved setting after a restart, alignment included, is fixed. And the newer 1.5" OLED screens from Waveshare, which stayed blank on earlier software, now work.

These notes cover everything since the `v2.6.3` tag. A few items (the update repair, the rev3 power-off fix and some documentation) reached the release branch in late August without a version change. A PiFinder that was installed fresh or updated after that already has them, and still reports 2.6.3. They are listed here because most units in the field do not have them yet.

## ⚠️ After You Update

- **The catalogs changed, and the first start is slower.** The update replaces the object database (about 24 MB to download), so it takes longer than a usual update. On the first start the PiFinder builds its catalog cache again. The main menu comes up as usual. On a rev4 the message **Catalogs Fully Loaded** appeared after about 2 minutes. Until that message, only the Messier, NGC and IC catalogs are available; the other catalogs, Named Stars included, fill in while you wait. Do not power off during these 2 minutes if you can avoid it; if you do, the next start simply builds the cache again. Later starts read the cache and skip the rebuild. What changed in the catalogs, and what moved or went away, is in [the catalog page](2.6.4-catalog.md).
- **Star lists open with names shown.** Planets, comets, and the star, double-star, asterism and variable-star catalogs now open in the names view, so you see "Mizar" or "RX Peg" rather than only a catalog number. The deep-sky catalogs and mixed lists (All Filtered, Recent, observing lists, name search) open as before. **SQUARE** still changes the view, and the PiFinder does not remember your choice between lists.
- **Your observations and observing lists keep working.** They store catalog designations, and those have not changed. An observation now also shows as observed under every other catalog entry of the same object.
- **Your alignment now belongs to the telescope that was active when you aligned.** After the update every telescope still uses your existing alignment, exactly as before. The next time you align, the PiFinder saves the result for the active telescope only. The other telescopes keep the old alignment until you align on them. If you use one telescope, nothing changes for you. If you use several, align once on each; from then on, selecting a telescope in the Equipment menu (or on the web page) also selects its alignment, with no message.
- **A saved alignment no longer disappears after a restart.** Before this release, leaving **Align (Day)** with a manual exposure, or choosing a manual value in **Camera Exp**, could erase the alignment you had just saved. You saw it only after the next restart. If you have been re-aligning after every restart, that should stop.
- **No setting is reset.** `default_config.json` has no new keys, so your configuration file gains nothing it did not have. One new hidden file, `.config.json.lock`, appears in `PiFinder_data` (and on the network share). It stops two parts of the PiFinder from saving settings at the same moment. Leave it alone; it is safe to delete, and it comes back.
- **SQM readings do not change on a standard unit.** The SQM now reads the gain the camera actually delivers (see "The SQM reads the frame it measures" below). A PiFinder running the shipped camera settings delivers the gain the SQM was calibrated at, so its reading is the same as on 2.6.3.

## New Features

### Each Telescope Keeps Its Own Alignment (#703, ADR 0047)

The alignment point says how the PiFinder sits on one particular telescope: which camera pixel lines up with the center of that telescope's eyepiece. It was one setting for all telescopes, so an owner who moves the PiFinder between a Dobsonian and a refractor had to align again at every switch, although the Equipment menu already knew which telescope was in use.

Now each telescope in your equipment list keeps its own point.

- **Aligning saves the point for the active telescope.** Both alignment screens and the reset key work on the active telescope.
- **Selecting a telescope selects its alignment**, on the device and on the web page. The switch is silent.
- **A telescope you have never aligned uses the old shared alignment.** That is why nothing changes on update, and why nothing in your configuration is converted. Copying the shared point into every telescope would look the same today, but it would make "never aligned" impossible to tell from "aligned", and it would rewrite every configuration file.
- **The Align screen starts from the active telescope's point** and forgets the star from an earlier alignment, so a SQUARE press cannot save another telescope's star for this one.
- **Deleting a telescope on the web page keeps the active telescope.** Before, deleting a telescope above the active one in the list selected the next telescope down, which now would also have changed the alignment.
- **The web page does not show or reset alignment.** Alignment is done on the device. Editing a telescope on the web page keeps its point.
- **A stored point that is not usable is ignored** when the configuration loads, and that telescope falls back to the shared point. Before, one bad value could make the whole equipment list fail to load and be replaced by the defaults.

Tested on a headless unit with two telescopes, measuring the distance between the aligned pointing and the camera center: the Dobsonian unaligned read 3.77°, aligned 0.90°; selecting the refractor gave 3.77°, and selecting the Dobsonian again gave 0.90°. The same on the web page. Checked on hardware on 2026-11-19.

### Named Stars, and a Rebuilt Catalog (#697, #671–#696)

- **Numerous catalog fixes, a new Named Stars catalog, and one object per star.** Everything that changed, what moved or went away, and what it means for your data is on its own page: [PiFinder 2.6.4: Catalog Changes](2.6.4-catalog.md).

## Fixes

### Settings Saved by One Part of the PiFinder No Longer Erase Another's (ADR 0048, #626)

The PiFinder runs as several processes (the screens, the camera, the web server, the position integrator), and each read its own copy of the settings when it started. A save wrote that whole copy back to `config.json`, so it erased anything another process had saved since. The running PiFinder kept the right value in memory, which is why the loss showed only after a restart.

That is what erased alignments (above). It also explains why the lens that 2.6.3 measures for itself could vanish from the configuration file the next time you changed any menu setting (#626), after which the unit measured it again on the next start.

Now a save reads the file, changes only its own keys, and replaces the file in one step, under a lock so two processes cannot save at the same moment.

### The 1.5" OLED Runs at 20 MHz (#701)

Some newer 1.5" OLED screens from Waveshare stayed blank. The 1.5" screen (SSD1351 controller, rev3 and earlier) was driven at 40 MHz, about twice the controller's rated maximum of 20 MHz; older panels tolerated that and newer ones do not. It now runs at 20 MHz everywhere the software drives that screen: the app, the splash screen, the screen-clear script and the bench tools. The rev4's 1.91" screen is unchanged at 40 MHz.

A full screen now takes about 13 ms to send instead of 6.6 ms, against a frame budget of 33 ms. Only the changed parts of the screen are sent, so most frames send much less.

### Rev3 Units Power Off Completely Again (#639, ADR 0034)

The rev4 has a power latch on GPIO14 that cuts the power at the end of a shutdown. The boot setting that drives it was applied to every board, and on a rev3 (or earlier, all Raspberry Pi 4B) nothing answers that line. A rev3 then hung at shutdown with **Shutting Down** on the screen and never reached its off state. The setting now applies to the Compute Module 4 only, and the firmware decides at every boot, so one SD image still serves both boards.

This is a change to the setup script, so it reaches a unit through a newly written SD card. Updating does not change the boot setup of a card you already have.

### Updates That Said "Complete" but Changed Nothing (#640, ADR 0035)

A PiFinder that was updated in place from 2.5.1 or earlier could not update to 2.6.0 or later. The download stopped on one file (a link to the plate solver, `python/tetra3`), and the update still reported success. That file is no longer part of the download; the update script now creates it.

- **If your PiFinder still shows 2.5.x after "updating", update again from the Software screen.** This time it works, with no SSH needed. Anything that was in the way is moved aside to `~/tetra3_old_<date>`, not deleted.
- **A failed update now says so.** The Software screen shows **Error on Upd** rather than **Ok! Restarting** when the download fails.
- **If you update by hand with `git pull`**, run `pifinder_post_update.sh` afterwards, as the in-app update does. A bare pull from 2.6.3 removes the link, and the PiFinder does not start without it.

### The SQM Reads the Frame It Measures (#666)

Two properties of the camera frame were assumed, not read. Both are now read.

- **The frame size.** Exposure sweeps archive the whole sensor, but the SQM's field width is for the cropped frame. Measuring a full frame read about 0.2 mag too bright. The device itself always measured the crop, so live readings do not move; this corrects replays of archived sweeps.
- **The gain.** The SQM now scales by the analogue gain the camera reports, against the gain its calibration was made at. A unit at that gain, which is every unit on the shipped settings, reads as before. The change protects readings if a driver or Raspberry Pi OS update ever delivers a different gain.

Both came out of an owner's sweeps from a 21.3–21.55 mag site, checked against three SQM-L meters that agreed to ±0.1 mag: the first dark-site data in the archive. In replays of the 66 archived sweeps that have a reference meter, mean absolute error goes from 0.251 to 0.230 mag. That gain is from the crop, so it improves the archive and the tools that replay it, not a live reading.

### Smaller Fixes

- **The Obs Lists screen uses the whole rev4 display** (#704). It showed only 3 lists below the selection box, with the box too high and not full width. It now draws like every other menu: 9 lines on rev4, the selection box in the center. On the 128 px screen the lines move down by 1 to 4 pixels, to match the other menus.
- **UP and DOWN in object details step through every entry of a list** (#678). When two entries of one list are the same object (M 31 and NGC 224, or one of about 600 NGC/IC duplicate pairs the new catalog joins), scrolling jumped back or stuck on the second entry. It now visits each entry once.

## Documentation

- **Which key confirms** (#654): the manual now says that **RIGHT** confirms on a confirmation screen and that **SQUARE** does not. A new rev4 owner spent a first night unable to confirm a shutdown, landing in the help screen instead.
- **Quick Start setup** (#651) is split into three parts: rotating the body, setting the PiFinder Type, and a reference for each type.
- **A wrong Lens setting looks like an exposure problem** (#652). The troubleshooting page now says so, and the parts list states the solver database's 10° to 30° field limit for anyone fitting another lens. This closes #613.
- **The GPS lock note** (#653) now puts the condition first: Push-To and the Planets and Comets catalogs need a location and time, from the GPS or entered by hand.
- **The DIY parts list warns against the Adafruit 2472 BNO055 board** (#641). It looks almost the same as the correct 4646 but has its pins in a different order.
- **Hardware files:** a rev4 parts list beside the board files, the rev4 dovetail with its hard stop in the correct place, and the back piece with its edge inserts restored.

## Developer Improvements

- **Five new ADRs**: 0034 (the power-off overlay is gated to CM4), 0035 (the `python/tetra3` link is untracked and the post-update script owns it), 0046 (catalog corrections are cited, checked and applied last), 0047 (the alignment point belongs to the telescope) and 0048 (config saves write only their own keys). 0036 to 0045 are in use on another branch.
- **The SQM decision records are now one**, `docs/adr/0022-sqm-measurement.md`, which keeps 0022's number because the others cited it. 0002, 0024, 0026 and 0028 are gone from the tree and their numbers stay unused. Their sections are now named in `docs/ax/sqm.md` and `docs/ax/sqm/CONTEXT.md`, which also gain "reported analogue gain" and "calibration analogue gain" as terms.
- **The catalog import** gained cited corrections applied as the final pass (`astro_data/corrections/*.toml`, 222 of them), star identity by Hipparcos number, Hipparcos positions and IAU names as supplementary sources, a match guard, and a WDS double-star rule. The build is reproducible: two builds with different hash seeds are byte-identical. `docs/ax/catalog.md` §9 describes it. The import needs `tomli` on Python 3.9 (`requirements_dev.txt` only; the device never runs the import).
- **`Config.active_target_pixel()` and `Config.save_target_pixel()`** are the only way to read and write an alignment point. `Telescope.target_pixel` is excluded from equality, because telescopes are found by value.
- **`Config` no longer has `dump_config()`.** A save goes through `_persist`, which merges under `fcntl.flock` on `.config.json.lock` and replaces the file atomically.
- **`UITextMenu._draw_item_text()`** draws one item's text, so a subclass can change how an item looks and keep the shared carousel layout. `UIObsList` is the first user.
- **CI**: the Python 3.9 workflows are pinned to `ubuntu-24.04`, because `ubuntu-latest` (26.04) has no Python 3.9 (#689). The Attic cache moves to `cache.pifinder.io` (#686). The UI tests no longer hang on the comet catalog's retry loop, which the harness's no-op `time.sleep` turned into a busy loop (#684).
- **A release playbook**, `release_notes/RELEASE-PLAYBOOK.md` (#644), replaces the root `RELEASE.md`.
- **The unit + smoke suite stands at 2,421 passing** (1,531 at 2.6.3). **Five new translatable strings** since 2.6.3 (`Named Stars` and four on the Software screen), across de, es, fr and zh, for 698 in all. `Enter Local Time` is translated again: 2.6.3's catalogs had marked it obsolete, so it showed in English.

## Known Sharp Edges

New in this release:

- **Switching telescopes changes the alignment without a message.** That is by design, but a telescope you have never aligned uses the old shared point, which may not suit it. Align once on each telescope you use.
- **The first start after the update takes about 2 minutes to load every catalog.** Only Messier, NGC and IC are there until **Catalogs Fully Loaded** appears. Measured on a rev4 (between 1:55 and 2:18); a rev3 has not been timed.
- **The 1.5" OLED's frame rate at 20 MHz has not been measured on a rev3** while slewing on the chart screen. The arithmetic says the send fits the frame budget; nobody has looked yet.
- **The rev3 power-off fix reaches only new SD cards.** A rev3 card written from an image that has the old setting keeps hanging at **Shutting Down**. It is safe to switch off at that point.
- **Barnard's six "a" dark nebulae** (B 44a and others) are still not loaded (#665).

Still open from 2.6.3:

- **Leaving the Focus screen sideways can leave the exposure held** for the rest of the session, while Settings → Camera Exp still reads "Auto". Re-select Auto, or restart.
- **Switching Camera Type does not clear a stored lens.** Re-select the lens after any Camera Type change.
- **A Nearby list stops at the 200 nearest objects**, and the RA sort works but cannot be selected from the Quick Menu (#630).
- **The 25 mm lens on an imx296 or imx462 cannot solve**, and the menu still offers it.
- **The 12 mm lens is only partly calibrated** (#612): its SQM zero point and f-number are still assumed.
